# 后台邀请码、用户身份与 AI 提示词模板设计

## 背景

本次需求包含三个后台管理能力：

- 后台管理增加邀请码管理机制。
- 后台用户管理增加用户身份升降级机制。
- 后台 AI 配置页增加默认提示词模板管理。

当前代码库已有可复用基础：

- `Invitation` / `InvitationUse` Prisma 模型已存在，注册接口已支持邀请码消费。
- `/api/admin/invitations` 已支持邀请码列表和创建。
- `User.role` 已支持 `ADMIN | VERIFIED_USER | USER`。
- `/api/admin/users/[id]` 已支持角色字段更新，并保护最后一个管理员不能被降级或禁用。
- `AiPromptTemplate` 模型和 `/api/ai-config/prompts` 已存在。
- `/admin/settings/ai` 已复用 `AiConfigPage`，其中已有提示词模板相关前端逻辑雏形。

## 已确认产品边界

### 邀请码管理

- 邀请码支持后台创建、查看、作废。
- 作废邀请码不删除数据库记录。
- 作废邀请码只影响未来注册或升级，不影响已经通过该邀请码注册成功的用户。
- 默认创建规则：最大使用次数 `1` 次，默认 `7` 天后过期。
- 管理员可以调整最大使用次数、过期时间，也可以选择不过期。
- 注册时使用已作废邀请码，应返回明确错误：“邀请码已停用”。
- 邀请码入口命名为“邀请码管理”，放在后台侧边栏“用户管理”附近。

### 用户身份升降级

- 仅支持三种身份：`普通用户(USER)`、`认证用户(VERIFIED_USER)`、`管理员(ADMIN)`。
- 后台用户管理页新增“更改身份”弹窗。
- 管理员选择新身份后需要二次确认再提交。
- 用户身份发生变化后，撤销该用户现有会话，要求重新登录。
- 后端继续保护最后一个管理员不能被降级或禁用。
- 角色变更写入审计日志，记录操作者、目标用户、旧角色、新角色。

### AI 提示词模板管理

- “默认提示词”就是系统提示词模板，不新增另一套默认值概念。
- 在 `/admin/settings/ai` 增加或完善“提示词模板管理”区域。
- 复用 `AiPromptTemplate` 和 `/api/ai-config/prompts`。
- 管理员可以编辑模板、保存模板、恢复系统默认模板。
- 页面展示模板是否已自定义、当前版本、更新时间。
- `article_evaluation` 模板如果没有 `{{content}}`，允许保存，但页面提示：“未包含正文变量，评估时系统会自动追加文章输入块”。
- 运行时继续保留兜底：自定义 `article_evaluation` 缺少 `{{content}}` 时自动追加文章标题、来源、内容类型、正文输入块。

## 推荐实现设计

### 1. 邀请码管理

新增后台页面：

- 路径：`/admin/invitations`
- 导航名称：`邀请码管理`
- 位置：后台侧边栏用户相关分组，靠近“用户管理”。

页面展示字段：

- 邀请码
- 状态：正常 / 已作废 / 已过期 / 已用完
- 创建人
- 最大使用次数
- 已使用次数
- 剩余次数
- 过期时间
- 创建时间
- 使用记录：用户名、显示名、使用时间

页面操作：

- 创建邀请码。
- 复制邀请码。
- 作废邀请码。
- 刷新列表。

后端补齐：

- 给 `Invitation` 增加 `status String @default("ACTIVE")`，取值 `ACTIVE | DISABLED`。
- `GET /api/admin/invitations` 返回 `status` 和可展示状态。
- `POST /api/admin/invitations` 支持：
  - `maxUses`，默认 `1`，范围 `1-1000`。
  - `expiresAt`，默认当前时间后 `7` 天。
  - `neverExpires`，为 true 时 `expiresAt = null`。
- 新增 `PATCH /api/admin/invitations/[id]`：
  - 仅管理员可调用。
  - 支持 `{ status: "DISABLED" }` 作废邀请码。
  - 不支持恢复，避免被误恢复已泄露邀请码。
- 注册接口消费邀请码前检查：
  - 不存在：`邀请码无效`
  - 已作废：`邀请码已停用`
  - 已过期：`邀请码已过期`
  - 已用完：`邀请码已被使用完`

审计日志：

- 创建邀请码：`action=create, resource=Invitation`
- 作废邀请码：`action=disable, resource=Invitation`
- 注册消费：保留现有注册审计，继续避免明文完整邀请码进入日志。

### 2. 用户身份升降级

前端调整：

- 在 `/admin/users` 操作列新增“更改身份”按钮。
- 点击打开弹窗，显示：
  - 目标用户：用户名、显示名、当前身份。
  - 新身份选择：普通用户、认证用户、管理员。
  - 影响提示：身份变更后，该用户需要重新登录。
  - 管理员相关提示：降级管理员会移除后台权限；升级为管理员会授予后台管理权限。
- 提交成功后刷新用户列表并 toast：
  - 升级：`用户身份已更新，该用户需要重新登录`
  - 降级：`用户身份已更新，该用户需要重新登录`

后端调整：

- 复用 `PUT /api/admin/users/[id]` 的 `role` 更新能力。
- 当 `role` 存在且不同于原角色时：
  - 校验角色只能是 `ADMIN | VERIFIED_USER | USER`。
  - 保护最后一个管理员不能降级。
  - 更新角色。
  - 调用 `revokeAllUserSessions(id)` 撤销目标用户会话。
  - 写审计日志，包含 `oldRole` 和 `newRole`。
- 如果提交的角色和当前角色相同，返回成功但不撤销会话，避免无意义登出。

### 3. AI 提示词模板管理

前端调整：

- 在 `/admin/settings/ai` 保留“服务配置”。
- 增加“提示词模板管理”区域，优先使用现有 `AiConfigPage` 中的模板数据结构。
- 每个模板展示：
  - 模板名称
  - 描述
  - 是否已自定义
  - 版本
  - 更新时间
  - 文本编辑区域
  - 保存按钮
  - 恢复系统默认按钮
- `article_evaluation` 模板增加变量提示：
  - 推荐包含 `{{title}}`、`{{sourceName}}`、`{{contentType}}`、`{{content}}`。
  - 缺少 `{{content}}` 时展示 warning，但允许保存。

后端调整：

- 复用 `/api/ai-config/prompts`。
- `GET` 保持返回模板定义、内容、默认内容、自定义状态、版本。
- `PUT` 保持保存模板。
- `POST` 保持恢复系统默认。
- 增加或完善测试，确保：
  - 非管理员不能读写模板。
  - 空模板不能保存。
  - 无效 key 不能保存。
  - `article_evaluation` 缺 `{{content}}` 可以保存。
  - 运行时会自动追加文章输入块。

## 权限与安全

- 三个后台能力均仅允许 `ADMIN` 使用。
- 用户角色变更、邀请码创建、邀请码作废、提示词保存和恢复都需要审计日志。
- 邀请码不做物理删除，避免审计链断裂。
- 用户角色变更后撤销会话，避免旧会话继续使用旧权限。
- 作废邀请码不影响已注册用户，避免误伤已有账号。
- AI 模板允许灵活编辑，但运行时保留正文输入兜底，避免 AI 未收到正文却生成评估结果。

## 测试计划

### 单元 / API 测试

- `/api/admin/invitations`
  - 管理员可创建默认 1 次、7 天过期的邀请码。
  - 管理员可创建不过期邀请码。
  - 非管理员不能创建和查看邀请码。
  - 管理员可作废邀请码。
  - 作废邀请码写审计日志。

- `/api/auth/register`
  - 使用正常邀请码注册为 `VERIFIED_USER`。
  - 使用已作废邀请码返回 `邀请码已停用`。
  - 使用已过期邀请码返回 `邀请码已过期`。
  - 使用已用完邀请码返回 `邀请码已被使用完`。

- `/api/admin/users/[id]`
  - 管理员可将 `USER` 升级为 `VERIFIED_USER`。
  - 管理员可将 `VERIFIED_USER` 升级为 `ADMIN`。
  - 管理员可将 `ADMIN` 降级为 `VERIFIED_USER`，但不能降级最后一个管理员。
  - 角色变化后撤销目标用户会话。
  - 角色未变化时不撤销会话。

- `/api/ai-config/prompts`
  - 管理员可保存提示词模板。
  - 管理员可恢复系统默认模板。
  - 非管理员不能访问。
  - `article_evaluation` 缺 `{{content}}` 可以保存。
  - 运行时 prompt 构建会补充正文输入块。

### Playwright E2E

- 管理员进入“邀请码管理”，创建邀请码，看到列表新增记录。
- 管理员作废邀请码后，列表显示“已作废”。
- 使用已作废邀请码注册，页面显示“邀请码已停用”。
- 管理员进入“用户管理”，打开“更改身份”弹窗，将普通用户升级为认证用户，成功后列表更新。
- 管理员尝试降级最后一个管理员，页面显示后端错误。
- 管理员进入“AI 配置”，编辑提示词模板并保存，刷新后内容仍存在。
- 管理员恢复系统默认模板，页面显示未自定义。
- `article_evaluation` 缺少 `{{content}}` 时页面显示提示，但允许保存。

## 非目标

- 不新增第四种用户身份。
- 不支持删除邀请码。
- 不支持恢复已作废邀请码。
- 不做邀请码批量导入。
- 不做 AI 提示词版本历史回滚，仅保留当前 `version` 自增和恢复系统默认。
- 不改变普通用户和认证用户现有业务权限边界。

## 交付顺序

1. 邀请码状态字段、作废接口、注册拦截和测试。
2. 邀请码后台页面和导航入口。
3. 用户身份变更弹窗、角色变更撤销会话、测试。
4. AI 提示词模板管理 UI 完善、提示变量提醒、测试。
5. Playwright 覆盖后台真实点击路径。
6. 运行 `pnpm lint`、`pnpm test`、`pnpm build`、`pnpm exec playwright test`。

## 剩余风险

- `Invitation.status` 需要 Prisma migration，部署时必须执行数据库迁移。
- 邀请码作废后不影响已有用户，这是产品确认行为，不应在后续实现中改为自动降级。
- AI 提示词模板可编辑后，管理员可能写出格式不稳定的 prompt；运行时只能兜底正文输入，不能保证模型一定输出高质量 JSON。
