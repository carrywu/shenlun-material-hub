# Article Detail, AI Evaluation, and IMA Sync Requirements

## Goal

修复申论素材采集与素材卡管理项目中，文章详情页、AI 评估来源、正文渲染、素材卡同步到 IMA、IMA 健康检查相关问题，确保用户看到的状态清晰、全中文、可追踪，且所有同步失败都有明确反馈。

## Problem List

### P0: 文章详情页英文状态泄漏

- 文章详情页的 select、option、placeholder、状态枚举展示必须全中文。
- 后端枚举值可以继续使用机器值，例如 `accept`、`reject`、`pending`、`success`、`failed`、`skipped`。
- 前端必须通过统一映射函数展示中文，不允许直接展示机器值。
- 检查文章列表、筛选页、详情页、素材卡页、同步记录页是否存在同类英文泄漏。

### P0: AI 评估来源不清

- 文章详情页必须能说明 AI 评估结果来自哪里。
- 需要区分：
  - `ai-runtime`: 真实 AI 运行结果。
  - `database`: 明确来源为数据库持久化结果。
  - `seed`: seed 脚本写入的数据。
  - `mock`: 测试或开发 mock 数据。
  - `unknown`: 历史数据或无法判断来源。
- 历史已有 AI 字段但没有来源元数据时，展示为“历史数据库记录 / 来源未知”，不能猜测为 mock 或 seed。
- 未评估文章显示“尚未评估”。
- 正文更新后，如果 AI 评估 hash 或评估时间已过期，继续展示旧评估，但提示“正文已更新，当前 AI 评估可能已过期，请重新评估”。
- hash 只允许管理员或开发调试区可见，普通用户前台不展示 hash。
- AI 重新评估入口仅管理员可用。
- AI 重新评估失败时保留旧评估结果，同时记录最近一次失败错误。

### P1: 文章正文格式与源网站不一致

- 详情页应优先使用结构化正文渲染。
- 如果有安全 HTML，保留段落、标题、列表、图片、表格、引用、加粗、链接等基础结构。
- HTML 必须 sanitize，禁止执行脚本和事件属性。
- 如果只有纯文本，至少按换行恢复段落。
- 图片相对路径按文章原始 URL 转为绝对路径。
- 图片加载失败显示中文占位，不破坏正文流。
- 正文清洗或降级诊断仅管理员或开发环境可见，普通用户只看清洗后的正文。

### P1: 素材卡管理页“批量同步”无反馈

- 未选择素材卡时点击批量同步，提示“请先选择要同步的素材卡”。
- 同步中按钮 loading，并禁用重复提交。
- 成功、失败、部分失败、跳过都必须可见。
- 批量结果必须区分：
  - 成功 X 条。
  - 失败 Y 条。
  - 跳过 Z 条。
- 失败项展示错误原因。
- 跳过项展示“已同步，未重复创建 IMA 文档”。

### P1: 文章详情页新增“同步到 IMA”

- 在“查看原文”右侧新增“同步到 IMA”按钮。
- 管理员和认证用户可见。
- 普通用户不可见或不可用。
- 同步目标始终使用当前登录用户自己的 IMA 配置。
- 如果当前文章有可同步素材卡，用户必须勾选素材卡后同步。
- 未确认素材卡显示但禁用，提示“请先确认后再同步”。
- 如果当前文章没有可同步素材卡，允许同步文章正文，但必须二次确认。
- 文章正文同步只允许已审核通过文章。
- 未审核或已拒绝文章不能同步到 IMA。

### P0: 全局 IMA 调用链路

- 所有 IMA 调用必须统一走 IMA service，不允许页面或 route 各自拼接请求。
- 需要支持：
  - 单张素材卡同步。
  - 批量素材卡同步。
  - 文章正文同步。
  - IMA 健康检查。
- IMA 配置缺失、endpoint 不可达、鉴权失败、IMA 返回 500 都必须结构化返回并显示中文错误。
- 新增健康检查接口 `GET /api/ima/health`。
- 在 `/settings/ima` 展示 IMA 状态和“检查连接”按钮。

## Locked Product Decisions

- 管理员和认证用户可以同步到 IMA；普通用户不可以。
- IMA 同步使用当前登录用户自己的 IMA 配置。
- 管理员在文章详情页只同步自己的素材卡或系统公共卡，不同步其他用户私有素材卡。
- 认证用户只能同步自己的素材卡。
- 文章正文同步仅允许 `adminReviewStatus = approved` 的文章。
- 有素材卡时，用户勾选素材卡同步；系统不自动选择某一张。
- 未确认素材卡显示但禁用，前端和后端都必须拦截。
- 无可同步素材卡时，用户可以同步文章正文，但必须二次确认。
- 重复同步按“当前用户 + 来源对象”判断；已成功同步过则跳过，不重复创建 IMA 文档。
- 内容变更后再次同步仍不自动覆盖或新建 IMA 文档；提示内容已变化，本期不做强制重新同步。
- 批量同步结果区分成功、失败、跳过三类。
- AI 重新评估仅管理员可触发。
- AI 重新评估失败保留旧结果，记录最近一次失败。
- 历史 AI 评估无来源字段时显示“历史数据库记录 / 来源未知”。
- hash 只在管理员或开发调试区展示。
- 正文清洗或降级提示只对管理员或开发环境展示。
- E2E 测试统一放在根 Playwright 配置使用的 `e2e/` 目录。

## Acceptance Criteria

- 文章详情页所有 select、状态、按钮、placeholder 用户可见文案为中文。
- 文章详情页不直接展示明显英文机器状态值。
- 未评估文章显示“尚未评估”。
- mock、seed、历史、真实 AI 评估来源可区分。
- AI 评估过期时有明确提示，普通用户不看到 hash。
- 正文不会挤成一整段，段落、列表、表格、图片基础结构可保留。
- HTML 渲染通过 sanitize，不执行 script 或事件属性。
- 素材卡批量同步一定有反馈。
- 文章详情页存在“同步到 IMA”按钮。
- IMA 成功、失败、部分失败、跳过都有明确 UI 反馈。
- IMA 配置页能展示健康检查状态。
- 所有新增接口有权限校验。
- 所有失败都有中文错误提示。
- Vitest 和 Playwright 覆盖核心路径。

## Validation Commands

按项目实际可用命令执行并记录结果：

```bash
pnpm lint
pnpm test
pnpm build
pnpm exec playwright test
```

如只执行目标 E2E，可使用：

```bash
pnpm exec playwright test --project=admin
```

如果验证因缺少数据库、服务或环境变量失败，必须记录具体缺失项、错误摘要和替代验证方式，不能写“全部通过”。
