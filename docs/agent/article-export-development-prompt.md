1. 导出 PDF——不带批注版；

## 三、已确认的产品需求

### 3.1 导出入口

文章详情页顶部增加一个“导出”下拉菜单：

```text
导出
├── PDF
│   ├── 不带批注版
│   └── 带批注版
└── Word
    ├── 不带批注版
    └── 带批注版
```

增加稳定测试标识，命名可参考：

```text
article-export-menu
article-export-pdf-clean
article-export-pdf-annotated
article-export-word-clean
article-export-word-annotated
```

必须确保键盘可访问、按钮具有明确的 `aria-label`，不要只依赖图标表达含义。

### 3.2 所有版本都应包含

- 文章标题；
- 来源名称；
- 发布时间；
- 文章类型；
- 摘要；
- 正文；
- 正文图片；
- 原文地址；
- 导出时间。

### 3.3 默认不导出的内容

- AI 评分；
- AI 摘要；
- AI 金句；
- 标签；
- 素材卡；
- 收藏、已读、忽略状态；
- 页面操作组件；
- 管理调试信息；
- 批注创建人；
- 批注创建时间。

### 3.4 不带批注版

不带批注版必须：

- 完全移除批注高亮；
- 不显示批注编号；
- 不显示批注列表；
- 不出现 `data-annotation-id`；
- 不出现批注 tooltip；
- 不留下任何批注 CSS 样式痕迹。

输出必须是一份干净文章正文。

### 3.5 带批注版

带批注版统一采用静态表现：

- 正文保留批注高亮；
- 被批注文本后添加编号，如 `[1]`；
- 文末增加“文章批注”章节；
- 每条批注包含：编号、原文摘录、批注内容；
- Word 第一版不生成原生审阅批注气泡；
- PDF 不依赖鼠标悬浮 tooltip；
- 同一段文本对应多条批注时允许显示 `[1][2]`；
- 批注编号按正文中首次出现的位置排序，而不是创建时间排序。

示例：

```text
推进基层治理现代化，必须坚持和发展新时代“枫桥经验”[1]。

文章批注

[1]
原文：坚持和发展新时代“枫桥经验”
批注：可用于基层治理、社会治理和矛盾化解类申论文章。
```

### 3.6 未定位批注

如果某条批注无法在正文中找到：

- 不得静默丢失；
- 不要在正文中错误插入编号；
- 仍加入文末“文章批注”；
- 明确标记“未定位到正文位置”。

### 3.7 无批注文章

用户选择“带批注版”，但当前文章没有批注时：

- 提示：`该文章暂无批注，将按不带批注版导出`；
- 继续导出；
- 不报错；
- 不禁用带批注版按钮。

### 3.8 权限与数据隔离

- 所有有权查看文章详情的登录用户均可导出；
- 只使用文章详情接口当前已经返回、当前用户有权查看的批注；
- 不额外调用无权限批注接口；
- 不扩大现有数据访问范围；
- 不允许管理员批注或其他用户私有批注被错误泄露；
- 不要为导出功能绕过现有鉴权或 RBAC。

## 四、技术方案约束

### 4.1 推荐依赖

优先使用：

```bash
pnpm add react-to-print docx file-saver
pnpm add -D @types/file-saver
```

若确认 `file-saver` 非必要，可使用原生 `Blob + URL.createObjectURL + a.download`，但必须写明理由并补测试。

不要引入完整办公套件、OnlyOffice、LibreOffice 服务或服务端 Chromium。

### 4.2 PDF

第一版 PDF 使用：

- `react-to-print`；
- 专用打印组件；
- 浏览器打印窗口；
- 用户选择“另存为 PDF”；
- A4 打印样式。

第一版不要实现：

- 服务端 `page.pdf()`；
- 后台异步 PDF；
- 批量 PDF；
- 服务端 Chromium。

PDF 打印样式至少满足：

- A4；
- 合理页边距；
- 中文字体使用系统字体栈；
- 标题不与正文粘连；
- 段落行距适合阅读；
- 图片最大宽度不超过内容区；
- 尽量避免标题、图片说明和批注条目跨页断裂；
- 不打印页面导航、按钮、侧栏、Toast、遮罩、调试信息。

### 4.3 Word

Word 必须生成真实 `.docx`：

- 使用 `docx`；
- 使用 `Document`、`Paragraph`、`TextRun`；
- 正文图片使用 `ImageRun`；
- 文件可被 Microsoft Word 和 WPS 正常打开；
- 不允许用 HTML 内容伪装成 `.docx`；
- 不允许只生成 `.doc`；
- 不使用 `html-docx-js`。

Word 需要保留基础结构：

- 一级标题；
- 来源与日期元信息；
- 摘要标题与摘要内容；
- 正文段落；
- 标题层级；
- 列表；
- 引用；
- 图片；
- 原文地址；
- 带批注版的正文编号和文末批注列表。

无需追求网页 CSS 的像素级还原，但必须保证结构正确、中文可读、段落清晰。

## 六、批注算法要求

项目现有 `ArticleContentRenderer.tsx` 已包含批注插入逻辑。开发前必须评估：

- 哪部分可以复用；
- 哪部分应该提取为纯函数；
- 是否会影响现有页面高亮；
- 是否需要保持空白归一化匹配；
- 是否能处理跨文本节点匹配；
- 是否会破坏正文 HTML。

必须满足：

1. 批注文本和正文匹配时折叠空白差异；
2. 支持批注跨 HTML 文本节点；
3. 编号按正文出现顺序稳定排序；
4. 多条批注命中同一文本时保留全部编号；
5. 完全相同或重叠批注不得破坏 DOM；
6. 未命中批注必须保留到文末；
7. 相同输入多次导出，编号顺序必须一致；
8. 不带批注版不能调用会插入 `<mark>` 的路径。

优先实现可测试的纯函数，不要把核心匹配逻辑埋在 React 事件处理中。

## 七、图片处理要求

### 7.1 通用规则

- PDF、Word 均尽量保留正文图片；
- 微信图片继续复用现有 `/api/proxy/image`；
- 处理相对 URL；
- 图片失败时显示：`[图片加载失败]`；
- 单张图片失败不得中断整篇导出；
- 图片加载必须有超时；
- 导出过程必须有 pending 状态；
- 快速重复点击不得创建多个并行导出任务。

### 7.2 PDF

打印前尽量等待打印区域图片进入稳定状态：

- 已成功加载；或
- 已失败并替换为占位文本；或
- 达到合理超时。

不要无限等待远程图片。

### 7.3 Word

Word 图片处理至少包括：

- 获取最终可访问 URL；
- 下载为 `ArrayBuffer`；
- 判断常见图片类型；
- 使用 `ImageRun`；
- 按原始宽高等比缩放；
- 限制最大显示宽度；
- 限制单图大小；
- 限制累计图片大小；
- 超出限制或下载失败时使用文字占位；
- 不因为 GIF、WebP 或未知格式直接让整篇导出失败。

请结合项目实际部署资源选择合理阈值，并在代码注释或交接文档中写清楚。

## 九、交互与错误处理

### 9.1 pending 防重复

四种导出操作必须共用或分别维护可靠 pending 状态：

- 导出中禁用其他导出选项；
- 快速连续点击只触发一次；
- 成功或失败后恢复；
- PDF 打印调用失败时恢复；
- Word 图片处理中出现局部失败也要继续生成。

### 9.2 Toast

至少覆盖：

- 无批注时降级提示；
- Word 导出成功；
- Word 导出失败；
- PDF 打印准备失败；
- 图片部分失败时可给非阻断提示；
- 不要用浏览器 `alert()`。

### 9.3 空正文

若文章没有可导出的正文：

- 不得生成只有标题的假成功文件；
- 应禁用导出或给出明确错误提示；
- PDF 和 Word 行为保持一致；
- 补测试。

## 十四、完成标准

只有同时满足以下条件才能认为任务完成：

- [ ] 文章详情页出现导出菜单；
- [ ] 四个导出选项可用；
- [ ] PDF 打印内容符合需求；
- [ ] Word 生成真实 `.docx`；
- [ ] 无批注版完全干净；
- [ ] 带批注版有正文编号和文末批注；
- [ ] 未定位批注不丢失；
- [ ] 图片失败可降级；
- [ ] 权限没有扩大；
- [ ] 防重复点击有效；
- [ ] Vitest 通过；
- [ ] 导出专项 Playwright 通过；
- [ ] build 通过；
- [ ] lint 通过；
- [ ] 全量 E2E 已运行，或对无法通过部分提供真实证据；
- [ ] TodoList 已更新；
- [ ] 交接文档已更新；
- [ ] Git 提交已完成。
