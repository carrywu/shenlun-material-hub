# 申论素材项目评估与开发方案

> 文档生成时间：2026-06-04  
> 项目地址：`shenlun-material-hub`  
> 技术栈：Next.js 16 + Prisma 7 + SQLite + React 19 + Tailwind CSS  
> **本文件仅供开发者查阅，不得公开展示给普通用户**

## 1. 评估结论

### 1.1 当前项目整体状态

项目整体架构清晰，核心采集链路和 AI 评估链路已基本打通，但在**用户体验**和**产品完整度**上存在明显短板：

- 正常跑通能力：✅ 可以采集文章、AI 评估、生成素材卡
- 路由与页面跳转：✅ 没有发现死链，所有快捷入口对应真实路由
- 状态反馈体验：⚠️ **严重不足** —— 生成素材卡没有成功 toast，只有内联文字进度提示
- UI 信息层级：⚠️ 文章详情页标题被 truncate，在窄屏会裁断；图片完全不展示
- 素材卡分类：❌ 当前 5 类与申论学习场景不匹配（太学术，不贴场景）
- 图片显示：❌ HTML 清洗时移除了所有图片，正文不展示图片
- AI 评估入口分散：⚠️ 文章详情页没有一体化"AI 评估并生成素材卡"按钮

**数据库现状（截至评估时）：**
- ContentItem 总计：192 条（172 website / 20 wechat）
- aiDecision accept：22 条，reject：1 条，未评估：169 条
- MaterialCard：7 张（全部 fact_summary 类型）

---

### 1.2 主要问题概览

| 优先级 | 问题 | 影响 |
|---|---|---|
| P0 | 生成素材卡无成功/失败 toast | 用户不知道操作是否成功 |
| P0 | AI 评估与生成素材卡入口割裂 | 用户需要两次操作才能完成主流程 |
| P0 | 文章详情页无 AI 评估按钮 | 单篇文章无法独立 AI 评估 |
| P1 | 公众号文章图片无法查看 | 微信文章正文无法完整阅读 |
| P1 | 素材卡分类不符合申论场景 | 核心功能价值大打折扣 |
| P1 | 标题 truncate 不完整 | 第一眼无法读全文章标题 |
| P2 | 部分按钮无明确文字提示 | 用户不知道点击后会发生什么 |
| P2 | 全局无 Toast/Notification 系统 | 所有操作反馈依赖 alert/进度文字 |
| P2 | 数据体裁标签中文化不完整 | contentType 英文值显示在部分场景 |

---

### 1.3 推荐开发优先级

```
P0（本周必修）：一体化 AI 评估 + 生成按钮、全局 Toast 反馈
P1（下周完成）：图片展示、素材卡分类重构、标题层级优化
P2（两周内）：批量操作 UX 优化、中文化整理
```

### 2.3 生成素材卡无成功提示

**现象：** 在文章详情页点击"生成素材卡"后，如果成功，前端只是重新 `fetchArticle()`，没有任何 toast 或 modal 提示。用户无法知道是否生成成功，也看不到生成了几张卡片，没有"查看素材卡"快捷入口。

**当前真实链路：**

```text
用户点击「生成素材卡」
↓
handleGenerateCard() 发 POST /api/content-items/[id]/generate-card
↓
API 检查：article.aiDecision !== "accept" → 返回错误
API 正常：生成一张指定类型素材卡，返回 201
↓
前端：生成失败 → setErrorInfo 显示在卡片内联
前端：生成成功 → fetchArticle() 刷新页面（无任何成功提示！）
```

**根因：**
1. 项目全局**没有 Toast 系统**（grep 全代码无 `toast` 使用）
2. `handleGenerateCard()` 成功分支只有 `fetchArticle()`，未显示任何反馈
3. 生成的素材卡需要滚动到页面底部才能看到，用户容易误以为没有成功

**另一个问题：** 按钮在 `aiDecision !== "accept"` 时被禁用且显示提示，但**没有触发 AI 评估的入口**。用户必须去文章列表页勾选再点击"AI 评估"按钮，流程割裂。

**涉及文件：**
- `src/app/articles/[id]/page.tsx` — handleGenerateCard (L331-352)
- `src/app/api/content-items/[id]/generate-card/route.ts` — API 端

**修复建议：**

1. 引入全局 Toast 系统（推荐 `sonner` 或 `react-hot-toast`）
2. 成功后调用 `toast.success("素材卡生成成功，已生成 1 张「事实摘要」")`
3. 新增「AI 评估并生成素材卡」一体化按钮

**推荐一体化流程：**

```text
用户点击「AI 评估并生成素材卡」
↓
按钮进入 loading：「正在评估...」
↓
if (aiDecision !== "accept"):
  POST /api/content-items/assess { ids: [articleId] }
  等待评估结果
  if (评估失败): toast.error("AI 评估失败: {reason}") → 结束
  if (reject): toast.warning("文章不适合作为素材，AI 已拒绝") → 结束
↓
评估通过或已通过 → 切换 loading 文字为「正在生成素材卡...」
↓
循环生成所有类型素材卡（或指定类型）
POST /api/content-items/[id]/generate-card
↓
成功: toast.success("✅ 生成完成，共生成 N 张素材卡")
失败: toast.error("生成失败: {reason}，可重试")
↓
fetchArticle() 刷新页面展示新素材卡
显示「查看全部素材卡」跳转入口
```

**新增 API 建议：** `POST /api/content-items/[id]/assess-and-generate`（幂等）

**验收方式：** Playwright 点击按钮 → 断言 toast 出现 → 断言素材卡列表增加。

### 2.5 素材分类不符合申论场景

**现象：** 当前素材卡类型（CardType）为 5 种工程化命名，未贴合申论备考实际场景：

这 5 类虽然有中文 label，但并不贴合申论学习者的实际需要：
- 没有"申论金句"类型
- 没有"对策表达"类型

**当前分类影响范围：**

4. `src/app/articles/[id]/page.tsx` (L89-95) — `CARD_TYPE_OPTIONS`
5. `src/app/cards/page.tsx` (L53-60) — `CARD_TYPE_TABS`
6. `src/app/page.tsx` (L108-114) — `cardTypeConfig`（Dashboard 统计）

### 2.6 公众号文章图片无法查看

**现象：** 微信公众号文章在文章详情页**完全不显示图片**，只显示提取后的纯文本。

**根因分析：**

采集层（`weRssNormalizer.ts`）中的 `cleanWechatHtml` 函数提取正文时，通过 `contentEl.text()` 提取的是**纯文本**，图片信息完全被丢弃：

```typescript
// weRssNormalizer.ts L83-86
let fullText = paragraphs.join("\n\n");
if (!fullText) {
  fullText = contentEl.text().trim();  // 纯文本，img 标签被忽略
}
```

此外，前端文章详情页以 `whitespace-pre-wrap` 方式渲染 `fullText`，是纯文本渲染，不能渲染 HTML：

```tsx
// articles/[id]/page.tsx L594-601
<div
  className="text-sm leading-relaxed whitespace-pre-wrap select-text"
  onMouseUp={handleTextSelection}
>
  {renderAnnotatedText()}  // 返回纯文本字符串
</div>
```

原始 HTML 存在 `rawHtml` 字段中，但**前端页面未使用 rawHtml 渲染**，只使用 `fullText`。

**微信图片防盗链说明：** 微信 CDN 对图片有防盗链保护（检查 `Referer`），直接在第三方页面加载 `wx.qpic.cn` 图片会 403。需要图片代理中转。

**数据库检查结果：**
- 现有 20 条微信文章中，`rawHtml` 已存储了清洗前的 HTML 片段（包含 `<img>` 标签但属性可能已被清洗）
- `fullText` 是纯文本（已清洗）

**推荐修复路径：**

1. **采集层修改**：在 `cleanWechatHtml` 中保留 `<img>` 标签，将 `data-src` 替换为 `src`（微信懒加载）
2. **存储层**：`rawHtml` 已存储原始 HTML，可直接复用
3. **前端渲染**：当文章来源为 wechat 时，改用 HTML 富文本渲染（需 DOMPurify 防 XSS）
4. **图片代理**：新增 `/api/proxy/image?url=...` 接口，将微信图片请求通过服务端中转

**安全要求（见 §5.7）：**
- 渲染 HTML 时必须使用 `DOMPurify` 清理
- 图片代理接口必须白名单限制域名（仅允许 `mmbiz.qpic.cn`、`wx.qpic.cn` 等微信 CDN 域名）
- 禁止 SSRF：严格限制协议为 https，拒绝私有 IP 地址

**涉及文件：**
- `src/services/collectors/wechat/weRssNormalizer.ts`
- `src/app/articles/[id]/page.tsx`
- 新增：`src/app/api/proxy/image/route.ts`

### 2.7 AI 评估与素材卡生成流程割裂

**现象：** 文章详情页没有"先评估再生成"的一体化入口，必须到文章列表页进行 AI 评估，再回到文章详情页生成素材卡。

**当前流程（割裂）：**

```
文章列表页：[AI 评估] → 跳转或点击文章 →
文章详情页：[生成素材卡]（disabled if aiDecision !== "accept"）
```

**推荐流程（一体化）：**

见 §2.3 中的"推荐一体化流程"。

**评估：当前是否已有 AI 评估单篇接口？**

当前 `POST /api/content-items/assess` 支持批量 ID，**可以传入单个 ID**，因此不需要新建 API，只需要在前端串联：

```typescript
// 伪代码：一体化按钮逻辑
async function handleAssessAndGenerate() {
  if (article.aiDecision !== "accept") {
    await fetch("/api/content-items/assess", {
      method: "POST",
      body: JSON.stringify({ ids: [articleId] }),
    });
    await fetchArticle();  // 刷新评估状态
    if (newAiDecision !== "accept") {
      toast.error("文章不适合作为申论素材：" + aiReason);
      return;
    }
  }
  await handleGenerateCard();  // 生成素材卡
}
```

**幂等保护：** 后端 `generate-card` 路由已有幂等检查：
```typescript
// generate-card/route.ts L72-82
const existingCard = await db.materialCard.findFirst({
  where: { contentItemId: id, cardType },  // 同类型已存在时返回 409
});
```
这意味着同一类型的素材卡不会重复生成，但用户并不知道 409 的含义，需要将 409 转换为友好提示：「该类型素材卡已存在，无需重复生成」。

## 3. 当前 AI 评估真实流程，仅供开发者查看

> ⚠️ 以下内容描述 AI 内部技术实现，不得展示给普通用户。

### 3.1 前端入口

**文章列表页批量评估入口：**
- 页面：`src/app/articles/page.tsx`
- 按钮：「AI 评估」（L312-324）
- 触发函数：`handleAssess()` (L213-245)
- 逻辑：自动选取当前页所有 `qualityStatus === "candidate" && !aiDecision` 的条目，或手动勾选后评估

**文章详情页：**
- 当前无独立"AI 评估"按钮
- 生成素材卡按钮在 `aiDecision !== "accept"` 时被禁用，但无法触发评估

### 3.2 后端 API

**批量评估 API：**
- 路径：`POST /api/content-items/assess`
- 文件：`src/app/api/content-items/assess/route.ts`
- 请求体：`{ ids: string[], retryFailed?: boolean, concurrency?: number }`
- 返回：`{ assessed, accepted, rejected, errors_count, errors }`
- 并发控制：`Math.min(10, concurrency ?? 3)`

**生成素材卡 API：**
- 路径：`POST /api/content-items/[id]/generate-card`
- 文件：`src/app/api/content-items/[id]/generate-card/route.ts`
- 请求体：`{ cardType: CardType }`
- 返回：`MaterialCard`（201）或错误（400/404/409/500）
- **前置条件**：`item.aiDecision === "accept"` 且 `item.fullText` 非空

### 3.3 AI Provider 与模型配置

- 使用：OpenAI SDK（`openai` npm 包）
- 兼容任何 OpenAI 兼容 API（OpenAI、Deepseek、通义千问等）
- 配置来源优先级：数据库（`AiConfig` 表，name=`"default"`）> 环境变量
- 环境变量：`AI_API_KEY` 或 `OPENAI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`
- 数据库中 API Key 加密存储，加密密钥来自 `AI_CONFIG_ENCRYPTION_KEY` 环境变量
- 支持切换模型：在 `/settings/ai` 页面修改 `model` 字段即可
- 客户端有缓存，配置更新后 `resetAiConfigCache()` 清除
- 代码位置：`src/services/ai.ts`

### 3.6 素材卡生成如何使用评估结果

- 生成前**必须** `aiDecision === "accept"`，否则 400 报错
- 生成时**不会重复调用评估**，直接使用已有的 `fullText`
- 生成复用文章的 `title`, `sourceName`, `fullText`（取前 4000 字）
- 当前仅生成**用户手动选择**的单一类型，不批量生成所有类型
- 去重：同一文章 + 同一类型的素材卡已存在时返回 409，**不会重复生成**
- 成功后更新 `processingStatus` 为 `"card_generated"`

### 3.7 失败处理与重试机制

**AI 请求失败（网络/超时/速率限制）：**
- `assessRelevanceWithRetry()` 封装了自动重试：默认 2 次重试，1s/3s 间隔
- 瞬态错误重试，永久错误（invalid key、invalid input）直接抛出
- 超时：默认 30s

**JSON 解析失败：**
- 评估：抛出 `AiServiceError("AI_RESPONSE_INVALID_JSON")`
- 素材卡：`parseAiJson()` 尝试从 markdown 代码块提取，仍失败则抛出

**数据库保存失败：**
- 失败时将错误信息写入 `aiAssessmentError` 字段
- 更新 `processingStatus` 为 `"failed"`

**用户侧提示：**
- 当前：`generate-card` 失败后，在页面卡片内显示 `errorInfo.message`（小字）
- 代码位置：`articles/[id]/page.tsx` L715-729
- **问题**：成功时无提示，失败时提示不显眼

### 3.8 当前风险与技术债

1. **无全局 Toast 系统**：所有成功/失败反馈靠内联文字或 `alert()`，非常原始
2. **旧版 AI 评分 API 保留**：`/api/content-items/[id]/score` 和 `SCORING_SYSTEM_PROMPT` 与新版相关性评估并存，可能混淆维护者
3. **素材卡生成不支持批量类型**：每次只生成一种类型，需手动多次操作才能生成所有类型
4. **AI 评估无单篇入口**：文章详情页无法独立触发评估，必须去列表页
5. **前端 `alert()` 仍在使用**：`cards/page.tsx`、`settings/ai/page.tsx` 多处
6. **图片代理缺失**：微信图片无法展示

```typescript
const ALLOWED_DOMAINS = ['mmbiz.qpic.cn', 'wx.qpic.cn'];
const PRIVATE_IP_REGEX = /^(10\.|172\.(1[6-9]|2[0-9]|3[01])\.|192\.168\.|127\.|::1|localhost)/;

function validateImageUrl(url: string): boolean {
  try {
    const parsed = new URL(url);
    if (parsed.protocol !== 'https:') return false;
    if (PRIVATE_IP_REGEX.test(parsed.hostname)) return false;
    return ALLOWED_DOMAINS.some(d => parsed.hostname === d || parsed.hostname.endsWith('.' + d));
  } catch {
    return false;
  }
}
```

## 10. 风险评估

| 风险 | 影响 | 解决建议 |
|---|---|---|
| 微信图片代理触发防盗链 | 图片仍无法显示 | 测试不同 Referer 头，部分图片可能无法代理 |
| 素材卡类型重构导致老数据 UI 异常 | 老卡片显示英文 enum | 提前运行迁移脚本，前端增加 fallback 显示 |
| DOMPurify 误删正文内容 | 文章阅读不完整 | 白名单宽松配置，充分测试 wechat 样本 |
| sonner Toast 与 Next.js RSC 冲突 | Toast 不显示 | 确保 Toaster 在 client component 中挂载 |
| AI 一体化按钮串联增加请求延迟 | 用户等待时间变长 | 在 UI 上分阶段展示进度（评估中→生成中） |

## 11. 开发执行建议

### 11.1 推荐执行顺序

```
第1步：引入 Toast（sonner），确认 layout 挂载正常
第2步：文章详情页加 Toast 成功/失败通知
第3步：新增一体化按钮，串联评估+生成

第6步：清理 alert()，统一错误处理
第7步：E2E 测试补全
第8步：pnpm build 验收
```

### 11.2 每一步完成标准

- Toast 系统：成功/失败操作后均有 toast 弹出
- 一体化按钮：点一下按钮完成评估→生成全流程
- 素材卡分类：前端下拉全部显示中文
- 图片渲染：wechat 文章可见至少一张图片（如有）

- Toast 系统：移除 `sonner`，恢复 `alert()`（影响最小）
- 素材卡分类：不执行迁移脚本，前端 `CARD_TYPE_LABELS` 补充 fallback
- 图片代理：API 路由返回 404，前端 `onerror` 隐藏图片
